# 卡片问答：0.5.4 开发版

卡片可以接收专用 Agent 会话中的问题，显示正文和选项，用语音或按键回答，再继续原任务。
会话仍由 Codex 保存；桥接维护运行连接和问题关联，不自行实现 Agent 会话系统。
本功能需要 **0.5.4 桥接和固件**，并使用新建的**桥接驱动会话**。
原有桌面转发会话保持原行为，现有桌面弹窗不会因此被接管。

## 已有桥接配置

等当前任务结束，停止桥接。然后在仓库运行以下命令；示例目录要替换成允许 Agent 工作的实际项目：

```powershell
.\tools\New-AgentSession.ps1 -WorkingDirectory 'C:\Projects\MyProject' -Name 'MirTar Agent'
.\tools\Start-Bridge.ps1
```

第一条命令创建并初始化新的 Codex 会话，向现有私有配置追加一个条目，保留原会话和设备绑定。
默认最多八条会话；脚本不会自动把已有桌面会话改成桥接模式，也不替换缺失或正在被其他进程占用的会话。
一次简短的初始化回复使会话能落盘，之后才能安全退出设置进程并恢复。
已有卡片主机绑定可继续使用，无需重新配对。在卡片进入会话选择页选择 **MirTar Agent**；
已在会话中时可长按上下切换。

默认配置为 `.private/bridge.config.json`。需要另一份配置时给两条命令都传 `-Config`。
命令只打印状态；实际会话 ID、工作目录和设备凭据保存在本地私有文件。

## 首次配置，无需桌面会话 ID

准备 Windows、Node.js 24.13+、Edge 和已登录且原生语音可用的 Codex。
安装依赖后运行：

```powershell
npm.cmd ci --ignore-scripts
.\tools\New-LocalConfig.ps1 -BluetoothOnly -BridgeOwned -WorkingDirectory 'C:\Projects\MyProject'
```

随后按[主机添加步骤](server-onboarding.zh_CN.md)完成 Add server 和启动桥接。
这条配置路径不要求先在桌面新建会话，不询问家庭 Wi-Fi；现有真实配置不会被覆盖。
如果初始化中途失败，保留生成的私有文件，重试 `New-AgentSession.ps1`；不要删除原有绑定配置。

## 在卡片上回答

1. 像原来一样 OK 开始说话，再按 OK 提交任务。桥接驱动模式会直接开始执行，无需打开桌面聊天激活。
2. Agent 追问时，卡片自动显示问题；上下翻阅长内容，OK 打开回答菜单。
3. 默认选“语音回答”：再按 OK 开始录音，再按 OK 结束；识别完成后回填当前问题。
   有选项时也可上下选择，OK 直接提交；一组最多三个问题，每个最多四个选项。
4. “跳过这组问题”保留已经回答的部分，跳过剩余问题；“返回问题”不提交任何答案。
   长按上下切会话，长按 OK 回首页；正在录音时长按 OK 取消录音并退出。

回答始终绑定原会话和原请求，不作为新任务入队。答案发送期间不能重复操作。
问题已关闭、过期或切换后，旧答案不会写入另一个问题。卡片断线后可重连恢复桥接中仍有效的问题。

## 会话、桌面和权限边界

`execution: "desktop"`（或省略）使用旧桌面转发模式；`execution: "bridge"` 由桥接启动和恢复。
请用设置工具生成新会话条目，不只给已有桌面 UUID 加一个模式标签。
桥接模式在所选工作目录使用 workspace-write 与 on-request 权限策略；超出允许范围的执行／权限审批
尚未提供卡片审批界面，不会由提问工具代为批准。

已验证：任务完成后的历史可由桌面接口读取；桥接退出后另一进程可恢复同一会话并继续上下文。
桌面 UI 实际接手、桌面与卡片同时写入、桥接崩溃后恢复未完成提问尚未验证或支持。
需要切换客户端时，先结束任务并停止桥接。卡片断连和桥接退出是不同的生命周期。
桌面专有工具不保证在 CLI 后端可用；桥接会话使用其本地 Codex 配置、技能和工具。

标记为秘密输入的问题会隐藏正文和选项，并禁用语音收集；可以显式跳过。
语音继续使用 Codex 原生识别，没有增加独立 ASR 服务或 API Key。
未知提交结果不自动重放。源配置、初始化回执和测试音频留在忽略的 `.private/`。

见[验证记录与实际覆盖](validation/agent-questions-0.5.4.md)。这是开发版，尚待卡片实机验收。
