# MirTar v0.5.4

MirTar now offers a dedicated Codex Agent session and a Windows background bridge, so a card can start work without
waiting for a desktop chat to become active. Existing desktop-forwarded sessions remain available.

## Changes since v0.5.2

- Install a current-user background bridge that starts after Windows login, with status/start/stop/restart/log commands,
  graceful shutdown, bounded failure retries and duplicate-instance protection.
- Initialize an empty session list with a saved default workspace, or select an existing project. Setup prefers the
  installed desktop Codex backend and resolves relocated Store executables without changing global model settings.
- Experimental card questions: receive a question from a bridge-owned session, answer by voice or choose an option,
  and continue the original request. Expired/secret questions and duplicate replies are guarded.
- Delete a selected computer with its connection settings and server-scoped pairing profile; durable recovery protects
  the other saved computers if deletion is interrupted.
- Handle an occupied bridge port cleanly and avoid duplicate manual startup when its managed task is active.

## Downloads and upgrades

- `MirTar-v0.5.4-windows-bridge.zip`: Windows runtime source and helpers; install dependencies locally.
- `MirTar-v0.5.4-source.zip`: full source, templates and development checks.
- `MirTar-full.bin`: public complete image, flash at **0x0**. It contains no personal preset and can replace stored settings.
- `MirTar.bin`: public application only, flash at **0x10000** with the existing compatible partition layout to retain NVS.
- `firmware-manifest.json`, `release-manifest.json`, `SHA256SUMS`: provenance and integrity checks.

Use matching 0.5.4 bridge and firmware for card questions. Keep personal configuration under ignored `.private/`.

## Validation and limits

TypeScript, 51 bridge tests, portal/C configuration/bond/deletion tests and public/personal bundle guards pass.
Real native-ASR/question tests and saved-session continuation were verified on separate test sessions. The owner
confirmed a physical Bluetooth voice/reply round-trip in legacy desktop-forwarding mode. Background management was
installed and checked on two Windows computers; this is not a physical acceptance claim for every firmware feature.

- Legacy desktop sessions still require desktop activation; use **MirTar Agent** for dedicated bridge-owned execution.
- Desktop and bridge cannot simultaneously own the same conversation. Finish work and stop the current owner before
  switching; the desktop may retain a writer until it exits. Automatic ownership handoff is not implemented.
- Card questions and Delete server still need complete physical-device acceptance. Secret input, execution/permission
  approvals, simultaneous desktop control and recovery of unfinished questions after a bridge crash are not supported.
- Windows and Codex are implemented. Other OS/Agent adapters and reply TTS remain future work.
- The badge/computer link can stay on Bluetooth or a trusted LAN; Codex itself still needs internet access.

## 中文

0.5.4 新增登录自动启动的 Windows 后台桥接、默认工作区与自定义目录、桥接驱动的专用 Agent 会话、
实验性卡片追问和语音／按键答复，以及按主机删除全部连接设置。

已有卡片可用 `MirTar.bin` 在 `0x10000` 更新应用、保留配置；完整公版 `MirTar-full.bin` 从 `0x0` 写入，
可能覆盖原配置和配对。公版没有作者 Wi-Fi、主机绑定或会话；个人镜像不在 Release 中。

旧桌面会话仍需激活；卡片独立操作请选择 MirTar Agent。同一会话暂不支持桌面和桥接自动交接或同时接管。
作者已确认旧转发模式的实机语音／回复闭环，卡片问答和删除功能仍需完整实机验收。
