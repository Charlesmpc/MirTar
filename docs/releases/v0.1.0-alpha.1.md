# MirTar v0.1.0-alpha.1

[简体中文](v0.1.0-alpha.1.zh_CN.md)

First M1 preview for FoloToy AI Passport, Windows, a trusted LAN and existing Codex desktop sessions. This is a prerelease with incomplete physical-device acceptance.

## Changes

- Enable the badge backlight at 80% after creating the startup UI. The previous application ran with PWM duty zero and appeared dark.
- Change the default bridge port to **TCP 28743** and add `-Port` to the local configuration helper. Restart the bridge and rebuild/reflash personalized firmware when changing its target port.
- Provide the card's Wi-Fi/binding/recording/display implementation, Windows bridge, native Codex voice input, agent/platform abstractions and placeholder configuration templates.
- Keep real configuration and firmware out of Git, with ignored private paths and a credential-checking pre-commit hook.

## Downloads

- `MirTar-v0.1.0-alpha.1-source.zip`: full source snapshot, including firmware sources and templates.
- `MirTar-v0.1.0-alpha.1-windows-bridge.zip`: bridge runtime sources, tests, helpers and templates; requires Node.js and local dependency installation. Start with the [Windows package guide](../windows-bridge-package.md).
- `release-manifest.json` and `SHA256SUMS`: source commit identity and asset checksums.

Configured badge firmware embeds Wi-Fi credentials and binding keys. **No configured firmware, ELF, private configuration or device logs are uploaded**, including to this private repository. Build personalized firmware locally using the [card quickstart](../device-quickstart.md). No placeholder firmware binary is supplied for flashing.

## Validation

- Build: the backlight-corrected personalized firmware built with ESP-IDF 5.5.6 / LVGL 9.5.0 and passed merged-segment verification. TypeScript checking passed.
- Host tests: five bridge tests and six credential-guard tests passed before release.
- Device tests: USB startup logs confirmed the original configured firmware started and reached Wi-Fi initialization; the device established a LAN TCP connection to the bridge. The user reported real badge speech arriving in the intended Codex desktop session while the display was dark.
- Unverified: the corrected image's physical backlight/display, reply rendering, sustained audio, long-running stability, multiple real sessions and power use. The user-reported input test applies to the original configured image, not the corrected image.

Only completed formal replies are displayed. TTS, reliable live tool progress/approvals, Cursor integration and other operating systems are outside this preview. Native Codex voice availability and quotas still apply. Transport is explicitly unencrypted on a trusted LAN, with HMAC device binding.
