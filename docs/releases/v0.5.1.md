# v0.5.1

Bluetooth connections that cannot complete binding for one minute now offer **Reset Bluetooth pairing** on the badge.
The owner must confirm with the buttons. Binary Bluetooth profiles are automatically owned by stable `server.id`.
Reset clears only that host's profile and rotates its badge identity; other hosts, application binding and Wi-Fi remain.
Reconnect and enter a fresh Windows PIN without manually configuring Bluetooth addresses or keys.

The bridge also delays application authentication until notification subscription succeeds, buffers the first handshake,
isolates obsolete connection callbacks, and retries/refetches GATT data after subscription failures. Diagnostic logs now
include subscribe timing and card encryption/disconnect status.

Add-server pairing is promoted from temporary staging to its server ID after physical confirmation. A/B banks separate
completed profiles from incomplete writes. Legacy global bonds remain untouched and unused; each host pairs once when
upgrading to the new scheme.

On 2026-10-25, the owner confirmed successful physical-device validation of v0.5.1.
This is owner-reported acceptance; detailed coverage is recorded separately in the [validation notes](../validation/server-onboarding-0.5.1.md).

Public firmware has no preloaded hosts or private credentials. Personal preset images remain local and must not be uploaded.
