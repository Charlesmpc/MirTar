# MirTar v0.3.1

[简体中文](https://github.com/Charlesmpc/MirTar/blob/v0.3.1/docs/releases/v0.3.1.zh_CN.md)

A handheld voice/display terminal for existing Codex desktop sessions on Windows.
Bluetooth LE is the default; trusted-LAN Wi-Fi remains available. The owner
reported a successful physical-card voice test after the Bluetooth fix.

## Changes

- Fix post-pairing GATT service discovery on Windows by enumerating services and
  selecting the MirTar UUID, rather than relying on the failing filtered query.
- Register the notification receiver before maintaining the connection so a
  bonded reconnect does not lose the badge's initial hello.
- Propagate negotiated MTU changes and add bounded stage/HRESULT diagnostic codes
  without logging passkeys, audio or conversation contents.
- Keep BLE/Wi-Fi on the same HMAC/session/audio/reply/no-replay protocol.
- Verify merged/segmented flash hashes even with Windows PowerShell `-WhatIf`.
- Update bilingual README/setup guidance and generic example machine names/paths,
  synchronize package/lockfile/firmware versions, and add privacy auditing and
  repeatable release packaging.

## Upgrade and downloads

Restart the updated Windows bridge. A working v0.3.0 badge does not need reflashing
solely for this fix. New local builds identify as v0.3.1.

- `MirTar-v0.3.1-source.zip`: complete source and placeholder templates.
- `MirTar-v0.3.1-windows-bridge.zip`: bridge/native helper source, startup and
  configuration helpers, tests and docs. Install Node dependencies locally.
- `release-manifest.json` / `SHA256SUMS`: source identity and asset checksums.

No personalized firmware, native helper binary, private configuration, recording
or device log is included. See [Windows setup](https://github.com/Charlesmpc/MirTar/blob/v0.3.1/docs/windows-bridge-package.md)
and [card setup](https://github.com/Charlesmpc/MirTar/blob/v0.3.1/docs/device-quickstart.md).

## Validation and limits

Native worker compilation, TypeScript, protocol and credential-guard tests pass.
Live tests completed two consecutive physical BLE reconnects, HMAC binding,
native session selection and acknowledged existing-reply writes. The owner
subsequently reported the voice test passed. This does not establish sustained
throughput, battery life, device reboot recovery, other computers or radio-switch
stability. See [validation](https://github.com/Charlesmpc/MirTar/blob/v0.3.1/docs/validation/bluetooth-0.3.0.md).

TTS/card reply playback, live tool progress/approval UI, Cursor and other host
operating systems are not implemented. Codex native voice access/quotas and
experimental-interface compatibility still apply. Wi-Fi is trusted-LAN plaintext;
Bluetooth uses authenticated encryption plus application binding.

## Public source and privacy

This public repository starts from an audited v0.3.1 source snapshot. Earlier
private development history is excluded. Current source, public Git history and
release assets are checked for known local credentials, common token/private-key
patterns, generated artifacts and identifying examples. Automated checks cannot
establish an absolute absence of sensitive information.

An isolated template firmware rebuild did not complete on the release host:
GCC's `-dumpmachine` query returned empty output during bootloader configuration.
No v0.3.1 firmware binary is published or claimed to have passed device testing.
A working, owner-tested v0.3.0 badge can keep using the updated Windows bridge.
