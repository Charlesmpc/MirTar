## 桌面实际执行依据

专用 **MirTar 验证** 桌面会话收到合成语音：在本机计算 `731 * 947`，不修改文件。原桌面 Agent 实际执行 PowerShell，退出码 0、输出 `692257`，正式回复 `692257 completed`。正式桥接产生了不同的原生执行轮次，包括 `01a16cf8-2ff0-7fa3-bb48-a2c2a1f43e26`、`01a16cff-34ce-7f70-a2f2-aa48972476e2` 和最终 Windows 媒体层隔离后的 `01a16dfc-56c2-7102-9bff-d574c445deec`；最后一次模拟器报告 `INPUT_CORRELATION_PASS`。没有新增卡片/桥接 ASR 服务或 API Key。测试后检查本任务 WebRTC 媒体进程，检查时没有遗留。

模拟设备上传 674 个 PCM 帧，转换后 13.4645 秒；音频在明确提交后才送入原生语音。这些数字仅描述测试录音，不是网络/识别性能或真机麦克风质量。真实测试覆盖一个专用桌面会话；两会话路由目前只通过替身适配器测试，还未对两个真实桌面会话验收。

## 首次真机启动与背光修正（2026-10-24）

首次实际配置镜像 SHA256 为 `e1ae21814ba20af0f368d4aaab42d752512cb4987ffda789056fe6fcc74efe06`，对应 ELF SHA256 为 `5ba675d8af7666ab86bf3addb781ae83dd00fe7c85578ec2f2a86a4c7d5e5bd4`。用户通过 USB 刷入后屏幕保持黑色。20 秒 USB 开机日志显示新的 ESP-IDF 5.5.6 引导程序加载 factory 应用，随后输出 `MirTar startup: heap=94204 largest=86016, microphone_idle=off` 和 Wi-Fi 初始化信息；本次没有捕获到 panic 或反复启动。两条 I2S 停用错误没有阻止程序继续启动，是否影响后续录音仍待验证。

用户确认有启动声音、没有背光。源码确认 BSP 将背光 PWM 初始化为零，而 MirTar 没有开启背光。现已在创建并渲染开机界面之后调用 `bsp_display_backlight(80)`。原镜像、匹配 ELF、配置和脱敏诊断日志保存在被忽略的 `.private/` 目录。重新编译成功不代表修正已通过真机验证：需要刷入修正版，确认开机画面可见、文字可读，再测试绑定与录音。实际配置镜像、私有配置和原始设备日志不得提交 Git。

设备 USB 标识还与已连接桥接端口的局域网邻居 MAC 对应，确认网络可达，但不代表已证明会话绑定或语音提交。背光修正已完成构建并通过镜像分段核对：完整镜像 SHA256 为 `7fe3a798738a051c460ce24ac2a2301c8eac9a815851a7d6f2c0cd358e43bb13`，2,477,488 字节、写入 `0x0`，匹配 ELF SHA256 为 `f8726e0230d119197993e327ebc9ed36388cdc0321879f9297bfb529079942a1`。嵌入配置未改变，也不是占位模板。本次只有 BSP 调用修正，没有重复运行 Host tests；仍需实际重刷并目视确认。本次 Agent 没有刷入修正版。
